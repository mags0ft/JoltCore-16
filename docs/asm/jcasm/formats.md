# Output formats

The output formats usable in JCASM are `b`, `B`, `r`, `x`, `p`. Each of them serves a different purpose and can be generated by supplying the respective assembler flags, as described [here](./flags.md).

Below, there is a list of all possible formats and their purpose, along with examples.

- **b** (standard formatted binary blocks, one line per instruction): helps to understand the composition of each command:
```
00000 001 011 000 00 1111 000 0
00000 010 010 000 11 00000101
00000 010 000 010 10 00000101
00000 000 000 000 01 1000 010 1
00000 001 001 001 00 1001 100 1
00001 010 011 100 00 0011 000 0
11111
```

- **B** (block binary format, each instruction has the same length):
```
000000010110000011110000
000000100100001100000101
000000100000101000000101
000000000000000110000101
000000010010010010011001
000010100111000000110000
111110000000000000000000
```
- **r** (raw ROM format):
```
(binary gibberish)
```

- **x** (hexadecimal text format, each instruction separated by spaces):
```
160f0 24305 20a05 185 12499 a7030 f80000
```

Use these options by writing all of those you want behind the `-f` flag for output formats (see [flags](./flags.md)), for example:

```
$ ./jcasm ./asm/programs/counter.asm -f bBrx
$
```

- **p** (preprocessor output format, no actual executable code):

    This option is a little special, as it does not really generate an executable. It is also invoking an export way earlier than the other output formats for the sake of debugging. If something doesn't work as expected and you suspect it's the preprocessor's fault, you can take a look at what is being generated using said option.
