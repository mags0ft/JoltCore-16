# Assembler flags

The JCASM accepts several different flags to alter its behavior. On this page, you're going to see all the different options available.

## General information about command usage

Running the JCASM without any input parameter will already tell us a little bit about how it is supposed to be used:

```
$ ./jcasm
usage: jcasm [-h] [-o OUTPUT] [-O] [-f FORMAT] [-d] [--noext] input_file
jcasm: error: the following arguments are required: input_file
$ ./jcasm --help
usage: jcasm [-h] [-o OUTPUT] [-O] [-f FORMAT] [-d] [--noext] input_file

Assembler targeting the JoltCore 16 CPU.

positional arguments:
  input_file

options:
  -h, --help            show this help message and exit
  -o OUTPUT, --output OUTPUT
                        The output file to write the resulting binary to.
  -O, --optimize        Whether to turn on basic optimizations.
  -f FORMAT, --format FORMAT
                        Which format(s) to use when exporting (possible: b, B, r, x, p)
  -d, --debug           Whether to generate debug information while compiling.
  --noext               Whether to leave out the format-specific extension (only works when building for one format)
```

## Flags for output formats

As discussed on the [output format page](./formats.md), the JCASM supports exporting your program builds into several different formats.
The currently available ones are:

- `b`: standard binary-like text format - space-separated blocks, newlines for each instruction
- `B`: binary-like text format without spaces for segmentation
- `r`: raw ROM format - exports into pure, machine-readable, binary ROM files
- `x`: hexadecimal output, each instruction being separated by spaces
- `p`: exports the result of the pre-processor, which is what is being fed into the rest of the assembler

The formats `b`, `r` and `x` are activated by default if this parameter is not specified. Thus, three individual output files are generated by default.

Another flag usable if only one format is specified is `--noext`, which will keep the assembler from automatically adding any format-specific file extensions

## Output path

You can specify the output path for the assembled file(s) using the `-o` or `--output` argument:

```
jcasm ./asm/programs/counter.asm -o ./asm/build/
```

If this is left unspecified, a file called `bin.out`, plus (if applicable) the respective format file extension, is created in the current working directory.

## Optimizations

As mentioned on the [respective page](./optimization.md), the JCASM can perform optimizations to your assembly code. To toggle these optimizations on, use the `-O` or `--optimize` flag:

```
jcasm ./asm/programs/counter.asm -O
```

**Important**: While trying to keep the program flow exactly the same, this is still in development and might introduce unexpected behavior. Use the `-d` or `--debug` flag to see if any optimizations are performed that could cause bugs you are encountering.

Per default, optimizations are turned off.

## Debugging

To get as much information on assembly as possible, you can specify the `-d` or `--debug` flag to get debug information from the assembler:

```
$ ./jcasm ./asm/programs/counter.asm -d
Debug Debug: enabled debug output
Debug Pre-processing: 3 definition(s) found
Debug Pre-processing: 1 pass(es) done
Debug Code generation: generating build for formats "brx"
Debug Code generation: compilation succeeded!
    6 instructions used (0.14 KiB)
    0.0% of 64.0 KiB ROM occupied
Debug Code generation: formatting build as "BIN"...
Debug Code generation: formatting build as "ROM"...
Debug Code generation: formatting build as "HEX"...
$
```

This needs to be activated manually. If the debug flag is not specified, the JCASM will be completely silent and not output anything at all. This is intended behavior.
